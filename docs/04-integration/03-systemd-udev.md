# systemd units and udev rules

## fprintd device access
The SPI sensor is not USB, so libfprint's stock USB udev rules do not apply.
Route B installs a drop-in that grants the daemon access to the exact validated
nodes:

`/etc/systemd/system/fprintd.service.d/10-fte3600-acpi-spidev.conf`
(`BindsTo=` + `DeviceAllow=` per companion), generated by the driver's
`fte3600-device-allow.sh`.

Route A instead ships `/etc/systemd/system/fprintd.service.d/override.conf`
containing `DeviceAllow=/dev/focal_moh_spi rw`.

## udev rules
Route B installs `70-fte3600-acpi-spidev.rules` and creates stable aliases
`/dev/fte3600-spi-FTE3600:*`, `/dev/fte3600-gpio-FTE3600:*` and
`/dev/fte3600-irq-FTE3600:*`.

## Verification
`scripts/40-verify.sh` checks module and PAM state; `systemctl cat fprintd.service`
shows the effective drop-ins.
